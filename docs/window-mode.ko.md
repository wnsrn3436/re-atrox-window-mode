# 아트록스 창모드 패치

아트록스 실행파일의 네 군데를 고쳐 800x600 창으로 실행되게 한다. 전체 화면으로 바꾸는 블록을 건너뛰고 해상도 설정 함수에는 늘 800x600 을 넘긴다. 시작할 때 화면 위치도 바꾸고 스크롤 함수에 넘기는 값은 8 로 나눈다.


## 대상

| 항목 | 값 |
|---|---|
| 게임 | 아트록스 v1.10 빌드 1 |
| 파일 | UPX 를 푼 `atrox.exe` (2,965,504바이트) |
| md5 | `b4c64c06c2afd830995ef497478718be` |

정품 `atrox.exe` (md5 `01d0c56a04f61ffa40d219eb0378154c`) 는 UPX 로 압축되어 있어서 코드가 그대로 보이지 않는다. `upx -d` 로 푼 파일이 위 표의 파일이다.

이미지 베이스는 `0x400000` 이다. 고친 곳은 전부 `.text` 섹션 안이고 `.text` 는 가상 주소 `0x401000` 이 파일 오프셋 `0x1000` 에 놓여 있다. 그래서 **파일 오프셋 = 가상 주소 - 0x400000** 이다.

| 섹션 | 가상 주소 | 파일 오프셋 | 파일 안 크기 |
|---|---|---|---|
| `.text` | `0x00401000` | `0x1000` | `0x1D4000` |
| `.rdata` | `0x005D5000` | `0x1D5000` | `0x4A000` |
| `.data` | `0x0061F000` | `0x21F000` | `0x86000` |


## 바꾼 바이트

| 가상 주소 | 파일 오프셋 | 원래 바이트 | 바꾼 바이트 | 의미 |
|---|---|---|---|---|
| `0x0057C626` | `0x17C626` | `0F 84 C0 00 00 00` | `E9 C1 00 00 00 90` | 전체 화면 블록을 늘 건너뛴다 |
| `0x00489521` | `0x89521` | `8B 40 28 50 E8 AD 80 F7 FF` | `EB C8 90 90 90 90 90 90 90` | 아래 코드로 점프 |
| `0x004894EB` | `0x894EB` | `CC` 13개 | `B8 01 00 00 00 50 E8 E1 80 F7 FF EB 32` | 해상도 모드 1 (800x600) 을 넘긴다 |
| `0x004DC496` | `0xDC496` | `BF 01 00 00 00` | `BF 00 00 00 00` | 시작할 때 화면 위치 |
| `0x0042D477` | `0x2D477` | `56 E8 FD 9D FD FF` | `EB 3C 90 90 90 90` | 첫 스크롤 호출을 아래로 돌린다 |
| `0x0042D481` | `0x2D481` | `53` | `90` | `push ebx` 를 아래로 옮긴다 |
| `0x0042D484` | `0x2D484` | `E8 8B 4F FD FF` | `EB 3A 90 90 90` | 둘째 스크롤 호출을 아래로 돌린다 |
| `0x0042D4B5` | `0x2D4B5` | `90` 11개 | `C1 FE 03 56 E8 BC 9D FD FF EB BD` | `esi` 를 8 로 나눠 첫 호출 |
| `0x0042D4C0` | `0x2D4C0` | `CC` 16개 | `C1 FB 03 53 E8 4B 4F FD FF EB BE 90 90 90 90 90` | `ebx` 를 8 로 나눠 둘째 호출 |

`0x004894EB`, `0x0042D4B5`, `0x0042D4C0` 은 함수 사이의 빈자리(`CC`, `90` 채움)라 새 코드를 넣는 데 썼다.


## 1. 전체 화면 블록 건너뛰기

`0x0057C626` 의 조건 점프는 `al` 이 0 이면 `0x0057C6EC` 로 건너뛴다. 건너뛰지 않으면 전체 화면용 블록이 이어진다. 이 블록은 `GetWindowLongA` / `SetWindowLongA` 로 창 스타일에서 `0x00C80000` 비트(제목표시줄과 시스템 메뉴)를 지운다.

```
0057C61D  84 C0              test al, al
...
0057C626  0F 84 C0 00 00 00  je   0x0057C6EC        ; 원본
0057C626  E9 C1 00 00 00     jmp  0x0057C6EC        ; 패치
0057C62B  90                 nop
0057C62C  8B B4 24 54 04 00 00  mov esi, [esp+0x454]
0057C633  6A F0              push -16              ; GWL_STYLE
0057C635  56                 push esi
0057C636  FF 15 A8 72 E6 00  call [GetWindowLongA]
0057C63C  25 FF FF 37 FF     and  eax, 0xFF37FFFF
0057C641  50 6A F0 56        push eax ; push -16 ; push esi
0057C645  FF 15 BC 71 E6 00  call [SetWindowLongA]
```

`JE rel32` 를 같은 목적지의 `JMP rel32` 로 바꿨다. `JMP` 는 한 바이트 짧아서 거리가 `0xC0` 에서 `0xC1` 로 늘고 끝에 `NOP` 하나가 남는다.


## 2. 해상도 모드를 1 로 고정

`0x004DC840` 은 해상도 모드를 받아 화면 크기를 정하는 함수다. 모드 0 은 640x480, 모드 1 은 800x600 을 쓴다.

```
004DC85A  E8 26 BD F2 FF        call 0x00408585      ; 전역 객체 0x00B1DE78 을 돌려준다
004DC85F  C7 40 20 20 03 00 00  mov  [eax+0x20], 800 ; 모드 1: 너비
004DC866  E8 1A BD F2 FF        call 0x00408585
004DC86B  C7 40 24 58 02 00 00  mov  [eax+0x24], 600 ; 모드 1: 높이
...
004DC899  E8 E7 BC F2 FF        call 0x00408585
004DC89E  C7 40 20 80 02 00 00  mov  [eax+0x20], 640 ; 모드 0: 너비
004DC8A5  E8 DB BC F2 FF        call 0x00408585
004DC8AA  C7 40 24 E0 01 00 00  mov  [eax+0x24], 480 ; 모드 0: 높이
```

`0x00489500` 함수는 전역 객체 `0x00B26DFC` 의 `+0x28` 값(옵션에 저장된 해상도 모드)을 이 함수(`0x0040787E` 를 거쳐 `0x004DC840`)에 모드로 넘긴다. `0x004015D7` 은 그 객체의 주소를 돌려주기만 하는 함수다.

```
0048951A  6A 01              push 1
0048951C  E8 B6 80 F7 FF     call 0x004015D7
00489521  8B 40 28           mov  eax, [eax+0x28]   ; 옵션에 저장된 모드
00489524  50                 push eax
00489525  E8 AD 80 F7 FF     call 0x004015D7
0048952A  8B C8              mov  ecx, eax
0048952C  E8 4D E3 F7 FF     call 0x0040787E        ; 0x004DC840(모드, 1)
```

`0x00489521` 의 9바이트를 빈자리 `0x004894EB` 로 가는 짧은 점프로 바꾸고 그쪽에서 모드 자리에 1 을 넣어 같은 호출을 한 뒤 `0x0048952A` 로 돌아온다.

```
00489521  EB C8              jmp  0x004894EB
004894EB  B8 01 00 00 00     mov  eax, 1
004894F0  50                 push eax
004894F1  E8 E1 80 F7 FF     call 0x004015D7
004894F6  EB 32              jmp  0x0048952A
```


## 3. 시작할 때 화면 위치

`0x004DC480` 은 `0x004DC840` 을 부르는 초기화 함수다. `edi` 에 1 을 넣고 그 값을 `0x004DC840` 호출의 두 인자와 `+0x48`, `+0x4C`, `+0x54` 필드에 쓴다. 이 1 을 0 으로 바꿔 게임이 시작할 때 화면이 가운데에 놓이게 했다.

```
004DC496  BF 01 00 00 00     mov  edi, 1            ; 원본
004DC496  BF 00 00 00 00     mov  edi, 0            ; 패치
004DC49B  8B CE              mov  ecx, esi
004DC49D  57 57              push edi ; push edi
...
004DC4C4  E8 B5 B3 F2 FF     call 0x0040787E        ; 0x004DC840(edi, edi)
...
004DC4F1  89 7E 48           mov  [esi+0x48], edi
004DC4F4  89 7E 4C           mov  [esi+0x4C], edi
004DC4F7  89 7E 54           mov  [esi+0x54], edi
```

필드 각각의 뜻은 추가 확인 대상이다.


## 4. 스크롤 이동량 줄이기

`0x0042D477` 부근은 계산한 이동량 `esi`, `ebx` 를 두 함수(`0x0040727A`, `0x00402414`)에 넘긴다. 창모드에서는 스크롤이 너무 빨라서 두 값을 오른쪽으로 3비트 쉬프트해 8 로 나눈 뒤 넘기게 했다.

```
; 원본
0042D473  8B 4C 24 18        mov  ecx, [esp+0x18]
0042D477  56                 push esi
0042D478  E8 FD 9D FD FF     call 0x0040727A
0042D47D  8B 4C 24 18        mov  ecx, [esp+0x18]
0042D481  53                 push ebx
0042D482  8B F0              mov  esi, eax
0042D484  E8 8B 4F FD FF     call 0x00402414
0042D489  8B F8              mov  edi, eax
```

```
; 패치
0042D477  EB 3C              jmp  0x0042D4B5
0042D479  90 90 90 90
0042D47D  8B 4C 24 18        mov  ecx, [esp+0x18]
0042D481  90                 nop
0042D482  8B F0              mov  esi, eax
0042D484  EB 3A              jmp  0x0042D4C0
0042D486  90 90 90
0042D489  8B F8              mov  edi, eax

0042D4B5  C1 FE 03           sar  esi, 3
0042D4B8  56                 push esi
0042D4B9  E8 BC 9D FD FF     call 0x0040727A
0042D4BE  EB BD              jmp  0x0042D47D
0042D4C0  C1 FB 03           sar  ebx, 3
0042D4C3  53                 push ebx
0042D4C4  E8 4B 4F FD FF     call 0x00402414
0042D4C9  EB BE              jmp  0x0042D489
```

원래 자리에는 `sar` 를 끼울 공간이 없어서 호출을 빈자리로 옮기고 그 앞에 `sar` 를 넣었다. 그다음 원래 흐름으로 돌아온다. 옮긴 `CALL` 은 위치가 달라졌으므로 상대 거리를 다시 계산했다. 원본의 `E8 FD 9D FD FF` 와 패치의 `E8 BC 9D FD FF` 는 둘 다 `0x0040727A` 를 부른다.

`sar` 는 부호를 유지하는 쉬프트라 음수(반대 방향) 이동량도 8 로 나뉜다.


## 직접 패치하기

1. 정품 `atrox.exe` 를 `upx -d` 로 풀고 md5 가 `b4c64c06c2afd830995ef497478718be` 인지 확인한다.
2. 헥스 에디터로 위 표의 파일 오프셋으로 가서 원래 바이트가 맞는지 본다.
3. 바꾼 바이트로 덮어쓴다. 길이는 원래 바이트와 같다.
